## 四、历史设计决策与原因

| 决策 | 原因（原文/可核实依据） | 来源 |
|---|---|---|
| **采用 Organic Warmth 设计系统**（CSS token 化） | 目标是「温暖 inviting × 精致 refined × 无 AI 塑料感」，服务 25-40 岁休闲度假用户 | `MASTER.md:1-6`、`:21-26` |
| **主色选陶土赤褐 Terracotta 而非橙红** | 原文：「温暖但不廉价（避免过度饱和的橙红色）」 | `MASTER.md:23` |

| **不用 Inter / Roboto / Arial / 系统默认字体** | 原文：「Inter 是 AI 设计的最常用字体，缺乏辨识度。Plus Jakarta Sans 有类似的几何骨架但更温暖，Playfair Display 则带来民宿平台需要的『家』的质感」 | `MASTER.md:34`（反模式）、`:138`（原因） |

## 七、给重设计执行者的最小行动建议
> 说明：本节属于**主代理视角的建议，不是约束**。执行者可自行取舍或完全无视。


1. **先定「首页宽度」唯一的真值**（`--container-max: 1200px` 还是 1280px），再决定是否顺手把 `Home.vue:417` 对齐 token（本文档 三、P1）。
2. **先定「字体怎么办」**（P5）：要么把字体本地化/换系统栈，要么明确接受 `Playfair Display` 在中国大陆降级。
3. **配色不要另起一套**（本文档 一、第 1 条）：主色 `#d45f2e` + 辅色 `#558555` + 暖灰中性色已被写进 token、被 SearchBar 落地、被写进简历（`01a01f08`：搜索模块 Organic Warmth 设计系统重塑）。
4. **首页复用现有子组件即可**，不要重写 `HeroBanner`/`HomestaySection`/`SearchBar` 的既有逻辑；如需新素材，先确认 `PromoBanner.vue` / `TrustBadges.vue` 这两个疑似死组件是否可用（P8）。
5. **改完必跑** `npm run build`；提交前 `npm run lint:check`。

阅读说明与范围

本图选择 POST /api/files/upload：要求已登录，Controller 拒绝空文件，调用 storeFile 检查配置允许的 MIME 和大小上限。MIME 来自上传元信息，不等于真实文件内容检测、病毒扫描或完整安全审计。

原始文件名取扩展名，使用 UUID 生成新文件名；按 avatar / homestay / review / common 分目录写到 file.upload-dir。存储方式是本地文件系统；Docker 的目录挂载另见部署图。

这个 Controller 返回 /api/files/{type}/{filename}，GET 文件接口公开可读。FileService.uploadFile 另有 /static/uploads/ URL 构造，WebConfig 配有对应静态映射；不能把两种路径强行画成同一响应。

头像上传会尝试更新当前用户头像 URL，数据库更新失败会记录日志但仍可返回文件上传成功。其他业务图片的引用保存由各业务接口承担，不宣称文件与所有业务记录在一个原子事务中。

批量上传、删除、旧头像清理与其他房源图片接口在此图折叠或省略。图中不添加未实现的 CDN、S3、签名访问或自动文件回收服务。

代码核对入口：FileController.java · FileServiceImpl.java · FileStorageConfig.java · WebConfig.java

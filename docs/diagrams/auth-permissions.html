阅读说明与范围

采用补偿性安全分层表达：知道当前用户是谁不等于允许访问任意订单。每层展示缓解的风险和剩余问题，不宣称最后一层消除所有风险。所有控制由后端代码在请求运行时执行。

普通用户登录由 AuthService 处理，AuthController 写入 homestay_token 的 HttpOnly Cookie。当前 setAuthCookie 未设置 Secure；本图不根据注释宣称生产环境一定启用 Secure，也不宣称没有任何 token 暴露渠道。

JWT 过滤器优先读 Cookie，兜底读取 Authorization: Bearer；有效 token 解析 userId 和 authorities 并写入 SecurityContext。部分公开路径直接跳过 JWT；无效 token 不建立身份，继续交由安全过滤链判断。

SecurityConfig 放行公开接口；/api/admin/** 要求 ROLE_ADMIN，/api/host/** 通常要求 HOST 或 ADMIN（前置特例另有规则）。部分 Controller 使用 @PreAuthorize。公开接口不等于可以跳过业务所需校验。

OrderAccessGuard 是 Agent 订单工具的校验器：读订单可为订单房客或所属房东，申请型写工具与确认执行要求该订单房客。其他业务服务各有归属与状态检查，不能把它画成全站每个接口都会经过的统一 Guard。

房客/房东/管理员的能力按具体接口判断；管理员不是每个订单 Guard 的默认例外。该图是已核对入口的职责说明，不是全仓库安全审计或无越权证明；WebSocket 的独立认证未展开。

代码核对入口：AuthController.java · JwtAuthenticationFilter.java · SecurityConfig.java · OrderAccessGuard.java · CheckInServiceImpl.java

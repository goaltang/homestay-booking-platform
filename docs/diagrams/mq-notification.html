MQ · 通知推送与降级

通知先落库，提交后事件发布消息；消费者调用 WebSocket 推送，异常通过重试队列回主队列。

阅读说明与范围

NotificationCreatedEvent 与 NotificationUnreadCountChangedEvent 在 AFTER_COMMIT 被监听；监听器也允许 fallbackExecution。事件、生产者与交换机在图中折叠为一个发布步骤。

消费者区分通知与未读计数两种消息；推送异常进入 60 秒 TTL 重试队列，最多重试 3 次，上限后 ACK 丢弃。重试重投失败则 NACK(requeue=false)。

通知内容已持久化，前端可通过 HTTP 接口读取历史与未读数。它不等于离线客户端一定接收到每一次 WebSocket 推送，也不等于客户端已确认展示。

当前生产者发送失败只记录日志，数据库提交到 MQ 发布之间没有 outbox 原子保证；MQ 关闭时 NotificationService 有直接 WebSocket 推送路径。图中不宣称绝不丢消息。

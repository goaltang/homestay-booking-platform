阅读说明与范围

日历读取先检查房东与房源归属，再 buildBaseDays → applyAvailability → applyOrders，最后汇总。先应用的日期锁、封房、预订与自定义价格可被后续订单展示覆盖，不应把日历看作只读库存表。

手动封房只接受 AVAILABLE / UNAVAILABLE。封房检查订单冲突及日期占用，写入 MANUAL 来源、原因、备注和操作人；仓库手动更新会排除 BOOKED 或带 orderId 的记录。日期范围均为开始日含、结束日不含。

下单由 BookingConflictService 在日期锁内检查重叠订单和日历占用，再 markAsBooked。markAsBooked 此时使用 order.getId，而订单 save 在其后；新订单 ID 可能尚未生成，因此不能宣称每条库存已可靠绑定订单 ID。

服务有 markAsAvailable 释放方法，但全仓库静态查找未见其调用；当前取消、退款主线也未见对应可售库存释放。故图中没有画取消后必然 AVAILABLE 的箭头，本轮只记录未修改。

独立数据库 locked / lockExpiresAt 字段与 Redis 日期锁不是同一个机制。日历可显示有效 LOCKED、BOOKED、CHECKED_IN、CHECKED_OUT 等状态，但不能将显示状态当作已证明不会超卖的并发约束。

本图折叠基础价格计算、批量价格更新和 CSV 导出；实际价格仍需结合统一计价图。

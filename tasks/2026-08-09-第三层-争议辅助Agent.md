# TASK: homestay3 AI客服Agent 第三层（争议辅助）— 管理员裁决建议草稿

## 任务目标
新增**争议辅助服务**：管理员在仲裁争议订单前，一键生成"裁决建议草稿"——汇总订单时间线 + 争议详情 + 历史相似案例，交给 LLM 生成结构化的裁决建议（含倾向 APPROVED/REJECTED 及理由）。管理员可参考草稿快速仲裁，但**最终审批权永远在管理员**（本服务只生成建议，绝不自动仲裁）。

## 项目位置
- 后端：`/mnt/d/homestay3/homestay-backend/`（Spring Boot 3, Java 17, Maven）
- 包根：`com.homestay3.homestaybackend`

## 背景（已核实的事实）

### 现有仲裁链路
- `AdminOrderController`：`POST /api/admin/orders/{id}/dispute/resolve`，`@PreAuthorize("hasRole('ADMIN')")`，body `{resolution: APPROVED|REJECTED, note}`，调 `disputeService.resolveDispute(id, resolution, note)`
- 争议入口（前几层已完成）：房东 `raiseDispute`、房客 `raiseDisputeByGuest`，订单进 `DISPUTE_PENDING`，管理员仲裁
- `DisputeRecord` 实体（`entity/DisputeRecord.java`）：orderId / disputeReason / raisedBy / raisedAt / resolution / resolvedBy / resolvedAt / resolutionNote —— **已解决的争议是现成的少样本数据**
- `DisputeRecordService`：`getDisputeRecordByOrderId(orderId)` 返回 `DisputeRecordDTO`；`getAllDisputeRecords(pageable)` 分页

### 可复用的现成组件
- `service/agent/LlmClient.java`：`chat(List<Map<String,String>> messages)` 返回模型文本。OpenAI 兼容。**注意**：它检查 `agentProperties.isEnabled()`，与客服 agent 共用配置（agent.llm.*），用同一个即可
- `dto/AgentChatResponse.java` 等 agent DTO 已有 pendingAction 模式可参考
- `entity/Order.java`：remark 字段存了状态流转记录（"争议发起 - 原因: xxx"、"争议仲裁 - 结果: xxx"），是订单时间线的重要来源；还有 disputeReason/disputeResolution/disputeResolutionNote 字段、refundReason/refundRejectionReason、checkInDate/checkOutDate/nights/totalAmount/status/paymentStatus
- `dto/MessageDTO.java` + `service/ChatService.getMessages(conversationId, userId, pageable)`：聊天记录
- `repository/ConversationRepository.java`：`findByHomestayIdAndHostIdAndGuestId(homestayId, hostId, guestId)` —— 可拿到订单对应会话
- `dto/OrderDTO.java`：已有订单全字段

### 现有代码风格
- Controller：`@RestController` + `@RequestMapping` + `@PreAuthorize("hasRole('ADMIN')")` + ResponseEntity<Map<String,Object>> + try-catch 分级（404/400/500）
- Service：接口 + impl，`@Service @RequiredArgsConstructor @Slf4j @Transactional`（只读操作可不加事务）
- 中文注释，行尾 LF

## 要实现的内容

### 1. 新增 DTO：`dto/DisputeAdvisorResult.java`
```java
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class DisputeAdvisorResult {
    private Long orderId;          // 订单ID
    private String orderNumber;    // 订单号
    private String disputeReason;  // 争议原因
    private String timeline;       // 订单时间线（文本，来自 remark + 关键字段）
    private String chatSummary;    // 聊天记录摘要（文本；无会话则"无聊天记录"）
    private List<String> similarCases; // 历史相似案例（每项一条简短文本）
    private String suggestion;     // LLM 生成的裁决建议草稿（markdown 文本）
}
```

### 2. 新增服务：`service/DisputeAdvisorService.java` + `service/impl/DisputeAdvisorServiceImpl.java`
方法：
```java
DisputeAdvisorResult generateAdvice(Long orderId);  // 管理员调，生成裁决建议草稿
```
实现要点：
1. **校验**：订单存在（`ResourceNotFoundException`），订单状态为 `DISPUTE_PENDING`（否则 `IllegalStateException("订单不在争议中，无法生成裁决建议")`）
2. **组装订单时间线**（timeline 字段）：
   - 基础字段：订单号、房源标题、客人名（username，注意脱敏不需要——管理员可见）、入住/退房日期、晚数、总金额、状态、支付状态
   - remark 文本（含状态流转记录，可能为空）
   - 争议字段：disputeReason、refundReason、refundRejectionReason（若有）
   - 组装成易读的文本块（用换行分隔，不要 JSON）
3. **聊天摘要**（chatSummary 字段）：
   - 用 `ConversationRepository.findByHomestayIdAndHostIdAndGuestId` 找会话（homestay/guest 从 Order 拿，host 从 `order.getHomestay().getOwner()` 拿）
   - 找到则 `chatService.getMessages(conversationId, null, PageRequest.of(0, 50))` 取最近 50 条，拼接"发送者: 内容"列表
   - 找不到会话或没有消息 → "无聊天记录"
   - **注意**：`getMessages(conversationId, userId, pageable)` 的 userId 参数可能是权限校验用——先看 `ChatServiceImpl` 实现，若传 null 会 NPE 就传 host 或 guest 的 id（看实现决定，以能跑通为准）；若该方法强制校验归属，可改用 repository 直查（`MessageRepository` 找 conversationId 下消息，按 createdAt 排序，取最近 50 条）
4. **历史相似案例**（similarCases 字段）：
   - `disputeRecordService.getAllDisputeRecords(PageRequest.of(0, 10))` 取最近 10 条**已解决**的争议（resolution 非空）
   - 排除当前订单自身的记录（orderId 不同）
   - 每条格式："订单{orderNumber} 争议原因:{disputeReason} 仲裁:{resolution} 备注:{resolutionNote}"
   - 若少于 1 条 → 空列表（LLM 提示里说明"暂无历史案例"）
5. **LLM 生成建议**（suggestion 字段）：
   - 用 `LlmClient.chat`，system prompt 写明角色（民宿争议仲裁助手）、输入材料（timeline + chatSummary + similarCases）、输出要求（裁决建议：倾向 APPROVED 还是 REJECTED、理由、参考政策、注意事项，markdown 格式、中文、简洁）
   - user message 里拼上组装好的材料
   - LLM 失败（AgentLlmException / IllegalStateException）时：**suggestion 降级为"LLM 生成失败，请人工查看以下材料自行仲裁"+ 原始材料**，不让整个接口 500（对齐 agent 兜底风格）
6. 返回 `DisputeAdvisorResult`

### 3. 新增 Controller：`controller/AdminDisputeAdvisorController.java`
```java
@RestController
@RequestMapping("/api/admin/disputes/advisor")
@PreAuthorize("hasRole('ADMIN')")   // 类级别
public class AdminDisputeAdvisorController {
    @GetMapping("/{orderId}/advice")  // 或 POST，选与项目风格一致
    public ResponseEntity<Map<String, Object>> generateAdvice(@PathVariable Long orderId)
}
```
- 成功：`{"success": true, "data": DisputeAdvisorResult}`
- ResourceNotFoundException → 404 / IllegalStateException → 400 / 其他 → 500（与 AdminOrderController 分级一致）
- `@CrossOrigin(origins = {"http://localhost:5173", "http://127.0.0.1:5173"}, allowCredentials = "true")`（与现有 controller 一致）

### 4. 单元测试：`src/test/java/com/homestay3/homestaybackend/service/impl/DisputeAdvisorServiceImplTest.java`
Mockito 风格（参照 `DisputeServiceImplTest`）：
- `generateAdvice_OrderNotFound` —— 订单不存在抛 ResourceNotFoundException
- `generateAdvice_NotInDispute` —— 订单非 DISPUTE_PENDING 抛 IllegalStateException
- `generateAdvice_Success_WithChatAndCases` —— 正常流程：verify LlmClient.chat 被调用、返回结果含 timeline/chatSummary/similarCases/suggestion
- `generateAdvice_LlmFails_Fallback` —— LlmClient 抛异常时 suggestion 降级、接口不抛
- `generateAdvice_NoChatNoCases` —— 无会话/无历史案例时字段为空列表/占位文本，仍正常返回
- （可选）`generateAdvice_SimilarCasesExcludeCurrent` —— 历史案例排除当前订单

**不做** Controller 层测试（与项目现有测试分层一致）。

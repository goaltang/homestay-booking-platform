# TASK：CompletableFuture 并行化——首页统计接口

项目：/mnt/d/homestay3/homestay-backend（Spring Boot 3.0.2 / Java 17 / Maven）
包根：com.homestay3.homestaybackend
**只改代码，不要 git commit / push。** 注释用中文。风格：Lombok @Slf4j + @RequiredArgsConstructor。
完成后必须跑 `mvn -o test` 全量测试（全绿是验收硬标准），报告用例数/失败数。

## 背景

HomeService.getStats()（首页统计接口 /api/home/stats 的数据源）当前**串行执行 5 个独立数据库 count 查询**：
1. homestayRepository.countByStatus(HomestayStatus.ACTIVE)          —— 房源总数
2. homestayRepository.countDistinctCityTextByStatus(ACTIVE)          —— 覆盖城市数
3. reviewRepository.countPublicReviews()                             —— 评价总数
4. reviewRepository.countPublicPositiveReviews(4)                    —— 好评数
5. 近 30 天订单数（orderRepository 条件 count，看现有代码实现）       —— 30 天订单

这些查询相互独立、无顺序依赖，是典型的"多路 I/O 串行 → 并行"改造点。

## 任务

### 改造 service/HomeService.java 的 getStats() 方法

1. 注入异步执行器（项目已有 AsyncConfig 定义了名为 `taskExecutor` 的 ThreadPoolTaskExecutor bean）：
   ```java
   private final @Qualifier("taskExecutor") java.util.concurrent.Executor taskExecutor;
   ```
   （HomeService 目前用 @RequiredArgsConstructor 构造注入，加这个字段即可；import org.springframework.beans.factory.annotation.Qualifier）

2. 把 5 个 count 查询改为 CompletableFuture 并行：
   ```java
   CompletableFuture<Long> homestayCountF = CompletableFuture.supplyAsync(() -> homestayRepository.countByStatus(HomestayStatus.ACTIVE), taskExecutor);
   CompletableFuture<Long> cityCountF = CompletableFuture.supplyAsync(() -> homestayRepository.countDistinctCityTextByStatus(HomestayStatus.ACTIVE), taskExecutor);
   CompletableFuture<Long> totalReviewsF = CompletableFuture.supplyAsync(() -> reviewRepository.countPublicReviews(), taskExecutor);
   CompletableFuture<Long> positiveReviewsF = CompletableFuture.supplyAsync(() -> reviewRepository.countPublicPositiveReviews(4), taskExecutor);
   CompletableFuture<Long> thirtyDaysOrdersF = CompletableFuture.supplyAsync(() -> <现有近30天订单查询>, taskExecutor);
   ```
3. 汇合：`CompletableFuture.allOf(...).join()`（或 get()），然后逐个 `.join()` 取值
4. **异常语义保持等价**：任一查询失败 → join 抛 CompletionException → 方法抛异常（与现状串行抛异常一致），不要 catch 吞异常
5. 后续计算逻辑（positiveRate 计算、DTO 组装）**一行不改**，保证返回值与改造前完全一致
6. 注意：
   - 方法上的 @Cacheable("homeStats")、@Transactional(readOnly = true) **保留不动**
   - 并行子任务里只做只读 count 查询，不要放任何写操作
   - 不要动其他方法

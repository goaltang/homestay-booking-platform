## 背景（已调研，直接照做）

## 任务 1：@OperationLog 注解 + 切面（全站管理员操作审计）

新建包 `annotation` 和 `aspect`（com.homestay3.homestaybackend.annotation / .aspect）。

### 1.1 annotation/OperationLog.java
```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface OperationLog {
    String operationType();          // CREATE / UPDATE / DELETE
    String resource();               // 模块名，如 BANNER、ANNOUNCEMENT
    String detail() default "";      // 支持 SpEL，如 "创建公告: #{#announcement.title}"
    String status() default "SUCCESS";
}
```

### 1.2 aspect/OperationLogAspect.java
- `@Aspect @Component`，`@Around("@annotation(operationLog)")`
- operator 获取：`SecurityContextHolder.getContext().getAuthentication()`，非空则 `getName()`，为空/匿名则 `"SYSTEM"`（principal 是 CustomUserDetails，实现 UserDetails，getName() 返回 username）
- IP 获取：`RequestContextHolder.getRequestAttributes()` 转 `ServletRequestAttributes` 取 `request.getRemoteAddr()`；无请求上下文则 null
- detail 解析：`SpelExpressionParser` + `StandardEvaluationContext`，绑定所有方法参数（setVariable 参数名 → 参数值）+ `#result`（返回值）；解析失败时 fallback 为注解原始字符串，**绝不能让日志解析异常影响业务**
- 调用 `operationLogService.log(operator, operationType, resource, resourceId, ipAddress, detail, status)`：
  - resourceId：优先 SpEL 支持（#id 之类），实现为：detail 和 resourceId 都支持 SpEL；resourceId 默认取 `#result?.id`（返回值的 id，若返回值为 null 或没有 id 则 null）
  - 整个 log 调用用 try/catch 包住，log.error 即可，不影响业务
- **只记录成功**（方法正常返回后记录；抛异常不记录——保持现有代码语义）
- 注意：OperationLogServiceImpl.log 本身是 @Async，切面直接注入 OperationLogService 接口调用即可

### 1.3 改造 AdminAnnouncementController
- 删除 `operationLogService` 字段注入和全部 5 处手动 `operationLogService.log(...)` 调用
- 在 createAnnouncement/updateAnnouncement/deleteAnnouncement/publishAnnouncement/offlineAnnouncement 方法上加注解，例如：
  - `@OperationLog(operationType = "CREATE", resource = "ANNOUNCEMENT", detail = "创建公告: #{#announcement.title}")`
  - `@OperationLog(operationType = "DELETE", resource = "ANNOUNCEMENT", detail = "删除公告")`
- 注意原代码 operator 是前端传的 publisherName 参数——改成从 SecurityContext 取是**有意为之**（防伪造操作人），这是行为改进不是 bug

### 1.4 改造 AdminSystemConfigController
查看它的手动 log 调用点，同样替换为注解（保持 detail 内容一致）。

### 1.5 全站覆盖：其余 Admin*Controller
遍历 `controller` 包下所有 `Admin*Controller`（**排除 AdminAuthController**——认证接口没有安全上下文）：
- 对每个 `@PostMapping/@PutMapping/@DeleteMapping/@PatchMapping` 方法加 `@OperationLog`
- resource = 类名去 Admin 前缀、去 Controller 后缀、转大写，如 `AdminBannerController → "BANNER"`、`AdminOrderController → "ORDER"`
- operationType 按 HTTP 方法：POST→CREATE、PUT→UPDATE、DELETE→DELETE、PATCH→UPDATE
- detail 默认不写（保持空），只有原本有手动 log 的 controller 保留 SpEL detail
- GET 方法**不加**注解
- 若某 controller 原本就手动调 log，先删手动调用再注解化（如 AdminAnnouncementController 的改法）

## 任务 2：@RedisLock 注解 + 切面（分布式锁注解化）

### 2.1 annotation/RedisLock.java
```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RedisLock {
    String key();                 // 支持 SpEL，如 "payment:notify:#{#result.outTradeNo}"
    long timeoutSeconds() default 30;
}
```

### 2.2 aspect/RedisLockAspect.java
- `@Aspect @Component @Order(1)`（**必须 @Order(1)**：确保锁在 @Transactional 事务开启前获取、事务提交后释放）
- `@Around("@annotation(redisLock)")`
- 注入 `com.homestay3.homestaybackend.util.RedisLock redisLockUtil`（注意与注解同名，命名避让）
- key 解析：SpEL + StandardEvaluationContext（绑定方法参数 + #result）
- 流程：
  ```java
  String requestId = redisLockUtil.generateRequestId();
  if (!redisLockUtil.tryLock(key, requestId, Duration.ofSeconds(timeoutSeconds))) {
      log.warn("获取分布式锁失败，跳过: key={}", key);
      return null;   // 保持原"跳过"语义（原代码 tryLock 失败直接 return）
  }
  try { return pjp.proceed(); } finally { redisLockUtil.unlock(key, requestId); }
  ```
- 切面自己内部 try/catch SpEL 解析失败时直接抛 IllegalArgumentException（锁 key 解析失败属于编码错误）

### 2.3 改造 PaymentServiceImpl.handlePaymentNotify
- 删除第 247-253 行（lockKey/requestId/tryLock/失败 return）
- 删除 finally 块里的 `redisLock.unlock(lockKey, requestId)`（原 290-292 行）
- 方法上加 `@RedisLock(key = "payment:notify:#{#result.outTradeNo}")`（参数名是 result）
- **保留**方法内部其余逻辑（@Transactional、状态检查、乐观锁 catch、异常处理）原样不动
- 保留 `redisLock` 字段导入？改造后不再使用则删除该字段和 import（检查是否还有其他使用点）

### 2.4 改造 NotificationCleanupService.cleanupOldNotifications
- 查看现有 RedisLock 用法（它是定时任务，无请求上下文），同样替换为 `@RedisLock(key = "notification:cleanup")` 固定 key（无 SpEL 需要）
- 删掉手写 lock 代码

### 2.5 明确不做
- **BookingConflictService 的 Redisson MultiLock 不改**（多日期多锁 + TransactionTemplate 复杂场景，不是本任务范围，动它风险大）

## 任务 3：ApiTimingAspect 接口耗时切面

新建 aspect/ApiTimingAspect.java：
- `@Aspect @Component`
- `@Around("execution(* com.homestay3.homestaybackend.controller..*(..))")`

- 不改任何行为，异常原样抛出

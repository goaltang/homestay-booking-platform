# 管理后台统计导出修复（双 bug）

日期：2026-08-12
引擎：opencode-go/deepseek-v4-flash
范围：/mnt/d/homestay3/homestay-backend + /mnt/d/homestay3/homestay-admin

## 背景

统计分析页（/statistics）的"导出数据"按钮是坏的，两个 bug 叠加：

1. 后端假 xlsx：AdminStatisticsController.java 的 exportStatistics（约 L170-189）生成的是 **CSV 内容**（StatisticsServiceImpl.exportStatistics 用 StringBuilder 拼逗号分隔文本），但响应头 Content-Disposition 文件名是 `statistics_xxx.xlsx`、Content-Type 是 application/octet-stream → 用户下载到打不开的假 Excel。
2. 前端假导出：src/views/statistics/index.vue 的 exportData（约 L320-334）调用 api/statistics.ts 的 exportStatistics（responseType: "blob"），但拿到响应后**没有任何下载动作**（没有 blob → URL.createObjectURL → a[download] 点击），只弹了个"导出成功" → 文件根本没下载。

参照物：src/views/audit/statistics.vue 的 exportStatistics（约 L827-872）是正确实现（前端本地生成 CSV + blob 下载），**不要改它**。

## 要求

1. 后端 AdminStatisticsController.exportStatistics：
   - 文件名 `statistics_xxx.xlsx` → `statistics_xxx.csv`
   - Content-Type 改为 `text/csv;charset=UTF-8`
   - 不改 StatisticsServiceImpl 的 CSV 内容生成逻辑
2. 前端 src/views/statistics/index.vue exportData：
   - 拿到 blob 后真实下载：URL.createObjectURL + 创建 a[download] + click + 释放 URL（写法参考 audit/statistics.vue L853-862）
   - 文件名固定 `statistics_{startDate}_{endDate}.csv`（startDate/endDate 是已有的 params 变量）
   - 保持"导出成功"提示
3. 验证：
   - 后端 `cd /mnt/d/homestay3/homestay-backend && mvn -o compile` 0 错误
   - 前端 `cd /mnt/d/homestay3/homestay-admin && npm run build` 0 错误（vue-tsc 严格模式）
   - 可选：起后端 + 登录 admin/admin888 后 curl `http://localhost:8081/api/admin/statistics/export` 带 Authorization Bearer token，确认响应头 Content-Disposition 是 .csv

## 约束

- 只改：homestay-backend/.../controller/AdminStatisticsController.java、homestay-admin/src/views/statistics/index.vue
- 不动 audit/statistics.vue、不动 api/statistics.ts 的 responseType
- 不 npm install / 不 mvn install 任何新依赖

## 坑

- WSL 挂载盘：npm run build 若报 rollup 平台错误，`npm i @rollup/rollup-linux-x64-gnu --no-save` 可修，除此之外不要动依赖
- mvn 用 `-o`（离线）跑，本地仓库在 D 盘 maven_repository

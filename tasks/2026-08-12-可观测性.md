## 任务清单

### 1. pom.xml 加依赖
- `org.springframework.boot:spring-boot-starter-actuator`（版本继承 parent 不用写）
- `io.micrometer:micrometer-registry-prometheus`（版本继承）
- 位置：与其他 spring-boot-starter-* 依赖放一起

### 2. application.properties 加配置
```
management.endpoints.web.exposure.include=health,info,prometheus,metrics
management.endpoint.health.show-details=always
management.metrics.tags.application=homestay
```
（放在文件合适位置，注释说明）

### 3. SecurityConfig 放行 actuator
在 permitAll 链加：`/actuator/health/**`、`/actuator/prometheus`、`/actuator/metrics/**`（参考现有 `/swagger-ui/**` 的写法）。注意 `/actuator/**` 全放行也可以但更推荐只放这三个。

### 4. 新建指标注册/埋点辅助（推荐放 `config/MetricsConfig.java`）
- 用构造注入 `MeterRegistry`（Micrometer 自动装配，无需手动建 registry）
- 提供静态方法或直接在各处注入 MeterRegistry 均可——**保持简单**：不要抽象过度。最简单方案是每个埋点处直接 `@Autowired MeterRegistry` 然后 `registry.counter(...).increment()`

### 5. 业务埋点（5 处，每处 3-8 行）
| 埋点 | 位置 | 指标 |
|---|---|---|
| 限流触发 | RateLimitAspect 超限抛异常前 | Counter `homestay.ratelimit.blocked`，tag `method=类名.方法名` |
| MQ 消费 | 三个 Consumer 成功消费后 | Counter `homestay.mq.consumed`，tag `scenario=order.timeout/coupon.batch/notification.push` |
| MQ 重试 | Consumer 收到重试队列消息时（消费时若消息来自重试队列或第 N 次消费） | Counter `homestay.mq.retried`，tag `scenario=...`。若判断重试来源复杂，可简化为：消费异常回滚时计数 |
| 订单超时取消 | OrderTimeoutService 取消订单处 | Counter `homestay.order.timeout.cancelled` |
| LLM 调用 | LlmClient 成功/失败 | Counter `homestay.llm.requests`，tag `result=success/failure`（失败计数在 catch 里） |
| 首页统计耗时 | HomeService 五路并行方法（方法级计时） | Timer `homestay.home.stats.duration`（用 `Timer.Sample` 或 `@Timed` 均可，注意 @Timed 需要额外依赖，优先用 Timer.Sample 手动计时） |

要求：
- 埋点**只加不改**：不改变现有业务逻辑、不改变异常处理路径（限流计数放在抛异常前，不影响降级放行逻辑）
- MeterRegistry 注入用构造器或 @Autowired 均可，保持一致风格
- 指标命名统一 `homestay.*` 前缀

### 6. 测试（新增 1 个测试类，够用即可）
`src/test/java/.../observability/ObservabilityMetricsTest.java`：
- `@SpringBootTest` + `@ActiveProfiles("test")` + `@AutoConfigureMockMvc`（或 TestRestTemplate RANDOM_PORT，参照现有 api/ 测试风格）
- 断言：`GET /actuator/prometheus` 返回 200 且 body 含 `homestay_ratelimit_blocked` 或 `jvm_memory`（prometheus 格式下点转下划线）——端点暴露验证
- 断言：调用一次限流接口或直接注入 MeterRegistry 断言 counter 存在
- 跑 `mvn -o test -Dtest=ObservabilityMetricsTest` 必须全绿

### 7. docker-compose.yml 加两个服务
```yaml
  prometheus:
    image: prom/prometheus:v2.45.0
    container_name: homestay-prometheus
    volumes:
      - ./tools/monitoring/prometheus.yml:/etc/prometheus/prometheus.yml
    ports:
      - "9090:9090"
  grafana:
    image: grafana/grafana:10.1.0
    container_name: homestay-grafana
    environment:
      - GF_SECURITY_ADMIN_USER=admin
      - GF_SECURITY_ADMIN_PASSWORD=admin123
      - GF_INSTALL_PLUGINS=grafana-piechart-panel
    ports:
      - "3000:3000"
    depends_on:
      - prometheus
```
- 新建 `tools/monitoring/prometheus.yml`：scrape_configs 抓 `host.docker.internal:8081/actuator/prometheus`（metrics_path=/actuator/prometheus，scrape_interval 15s）。注意 WSL/Docker Desktop 场景用 `host.docker.internal` 访问宿主后端
- 新建 `tools/monitoring/grafana-dashboard.json`：一个 dashboard JSON，含 4 个面板：
  1. JVM 堆内存（jvm_memory_used_bytes，area=heap）
  2. HTTP 请求量（http_server_requests_seconds_count）
  3. 限流触发次数（increase(homestay_ratelimit_blocked_total[5m])）
  4. 首页统计耗时（homestay_home_stats_duration_seconds 相关，可用 histogram_quantile 或直接 max）
  - 面板数据源 uid 用 `prometheus`，时间范围 last 30m
  - JSON 可直接手写（参考 Grafana dashboard 格式：panels/targets/datasource/uid/title/gridPos）
- 可选：`tools/monitoring/grafana-provisioning/datasource.yml` 自动注册 Prometheus 数据源（推荐做，省手动配置）

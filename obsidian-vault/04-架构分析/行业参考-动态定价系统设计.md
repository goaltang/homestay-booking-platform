# 行业参考：动态定价系统设计

> [!info] 说明
> 本文汇总 Airbnb、途家、美团民宿及第三方定价工具的行业实践，作为系统定价引擎迭代的参考输入。
>
> 核心原则：**营销活动解决补贴/优惠，价格引擎解决"这晚本来应该卖多少钱"**。

---

## 一、Airbnb Smart Pricing（平台内置，免费）

### 设计特点

| 维度 | 说明 |
|------|------|
| **定价边界** | 房东设定最低价和最高价，算法只在区间内浮动 |
| **优化目标** | 优先**最大化预订量**（booking probability），而非房东收入 |
| **平台利益冲突** | Airbnb 从每笔订单抽成 14-16%，天然有动力"降价换入住率" |
| **数据输入** | 房源属性、搜索热度、附近相似房源的预订和定价、日历空置情况 |
| **更新频率** | 每日自动调整 |
| **房东控制权** | 可随时在日历上手动覆盖任何日期的价格 |

### 房东实际反馈

- 普遍认为 Smart Pricing **系统性偏低定价**，为了保入住率牺牲了 ADR（平均房价）
- 大量专业房东（6+ 房源）转用第三方付费工具
- 适合 1-2 套房源、不愿投入时间的业余房东

---

## 二、第三方专业定价工具（PriceLabs / Wheelhouse / Beyond Pricing）

**订阅制 SaaS（约 $20-30/月/房源），行业真正的"动态定价"主力。**

### 核心能力矩阵

| 能力 | 说明 |
|------|------|
| **实时市场数据** | 持续监控竞品价格、搜索需求波动、本地活动 |
| **多因子模型** | 季节、星期、提前预订天数、空置率、当地事件、历史预订窗口 |
| **规则引擎** | 房东可设：最低价、最高价、周末溢价%、临期折扣曲线、连住折扣 |
| **多平台同步** | 同时更新 Airbnb、Booking.com、VRBO 等 |
| **Booking Window 意识** | 识别"Christmas 订单 90% 在 10 月完成"，提前布局定价 |

### 典型定价策略组合

```
基础价（由竞品中位数 + 房源质量分确定）
  ├─ 周末溢价：+15%（周五六）
  ├─ 季节性：旺季 +40% / 淡季 -10%
  ├─ 活动期：演唱会/会展期间 +80~200%
  ├─ 远期溢价：90天前 +20%（早期规划者愿意付溢价）
  ├─ 临期折扣曲线：
  │     14天未订 → -5%
  │      7天未订 → -10%
  │      3天未订 → -15%
  │      1天未订 → -20%
  └─ 连住折扣：7晚 -10%，28晚 -25%
```

### 工具对比

| 工具 | 优势 | 劣势 |
|------|------|------|
| **PriceLabs** | 规则灵活、多平台同步强 | 学习曲线陡 |
| **Wheelhouse** | 算法透明、数据可视化好 | 价格偏高 |
| **Beyond Pricing** | 易上手、适合新手 | 规则粒度粗 |

## 三、途家 / 美团民宿（国内 OTA 思路）

### 途家：动态跟价 + 机器学习

- 途家招聘 JD 中明确提到用 **GBDT / Deep Learning** 预测供需关系
- 输入特征：千万级房源数据、用户评论、交易行为、搜索点击
- 输出目标：优化 GMV 的定价策略
- 2025 年房东大会宣布引入 AI 定价

### 美团：自动抢单 + 即时决策

- 美团用户偏向**本地即时决策**
- 更强调**实时竞价**和**闪购促销**
- 侧重"最后一分钟"的价格弹性

### 国内通用"四阶段调控法"

> 来源：民宿运营实操总结，与酒店收益管理（Yield Management）思路一致。

| 阶段 | 时间窗口 | 策略 | 调价频率 |
|------|---------|------|---------|
| **远期期** | 60-90天 | 基础价 = 竞品均价 × 110-120%，筛选高净值客户 | 每周 |
| **黄金预售期** | 30-60天 | 预订率<30%→降价5%；>60%→涨价3-5% | 每10天 |
| **临近期** | 7-30天 | 接入竞品监控，最低价=竞品均值×0.9，最高价=竞品峰值×1.2 | 每日监测+隔日调整 |
| **最后窗口期** | 0-7天 | 博弈论算法：剩余>50%阶梯降价，<30%逆向涨价造稀缺 | 实时 |

### 核心心法

> **满房 ≠ 收益最大化**，关键是找到**价格与入住率的最优平衡点**。
>
> 动态定价的本质是**用价格作为筛子**，在不同阶段过滤出支付意愿最强的客群。

## 四、Airbnb 学术论文模型（KDD 2018）

> **论文**: *Customized Regression Model for Airbnb Dynamic Pricing*
>
> **作者**: Peng Ye, Julian Qian, et al. (Airbnb, Ant Financial, Impira)
>
> **链接**: https://dl.acm.org/doi/pdf/10.1145/3219819.3219830

### 三阶段架构

```
┌────────────────────────────────────────────────────────────┐
│  Stage 1: 预订概率预测（GBM 二分类）                        │
│    → 输入：房源特征、日期特征、用户行为、位置自适应采样      │
│    → 输出：该日期以价格 P 被预订的概率                       │
├────────────────────────────────────────────────────────────┤
│  Stage 2: 最优价格回归（定制化损失函数）                     │
│    → 基于需求曲线，找到"预期收益 = 价格 × 预订概率"的最大值  │
│    → 损失函数区分"正样本（已成交）"和"负样本（未成交）"      │
│    → 低需求场景：概率↑→价格缓慢增长后快速跳升                │
│    → 高需求场景：概率↑→价格快速增长后趋于平缓                │
├────────────────────────────────────────────────────────────┤
│  Stage 3: 个性化后处理                                      │
│    → 结合房东历史偏好、房源独特性、市场供需做最终调整        │
│    → 输出 Price Tips（建议价）或 Smart Pricing（自动价）     │
└────────────────────────────────────────────────────────────┘
```

### 关键评估指标

| 指标 | 英文 | 含义 | 目标 |
|------|------|------|------|
| **PDR** | Price Discovery Rate | 算法建议价低于真实成交价且被预订的比例 | 越大越好 |
| **BR** | Booking Regret | 算法定价低于实际成交价的遗憾值 | 越小越好 |

### 核心洞察

- 传统收益管理假设"大量相同产品"，但 Airbnb 每个房源都是**异质品**
- 无法直接估计需求曲线，必须用**机器学习方法**拟合"价格 → 预订概率"的映射
- 使用**基于位置的自适应采样**解决数据稀疏问题

## 五、酒店业传统 RMS（收益管理系统）

大型酒店集团（万豪、希尔顿等）使用的成熟框架：

| 模块 | 功能 | 民宿平台可借鉴度 |
|------|------|----------------|
| **竞争集（Comp Set）监控** | 选定 5-10 家直接竞品，每日抓价 | ⭐⭐⭐ 高 |
| **需求预测（Demand Forecasting）** | 历史预订曲线 + 当前进度，预测未来每天需求 | ⭐⭐⭐ 高 |
| **价格优化（Price Optimization）** | 线性规划求解：容量约束下最大化 RevPAR | ⭐⭐ 中 |
| **置换成本分析（Displacement Cost）** | 评估"接低价长住单" vs "留房给高价散客" | ⭐⭐ 中 |
| **超额预订（Overbooking）** | 基于取消率预测，主动超售降低空置 | ⭐ 低（民宿信任成本高） |

### RevPAR 公式

```
RevPAR = ADR（平均房价） × Occupancy Rate（入住率）
```

酒店 RMS 的核心就是在这个公式里找最优解，而非单纯追求满房或高价。

## 六、层级对比：我们系统目前在哪一层？

| 层级          | 代表                    | 自动化程度     | 我们系统            | 下一步动作                  |
| ----------- | --------------------- | --------- | --------------- | ---------------------- |
| **L0 固定价**  | 个人房东手动设置              | 无         | ❌ 已过            | —                      |
| **L1 规则引擎** | 周末/节假日/早鸟/连住规则        | 手动配置      | ✅ **当前在这里**     | 完善房东日历调价               |
| **L2 建议型**  | Airbnb Price Tips     | 算法建议，人决策  | ⚠️ 有竞争力分析但未接入定价 | 建议价 API + 前端展示         |
| **L3 半自动**  | Smart Pricing（设边界后自动） | 人定边界，算法执行 | ❌ 未实现           | 新增 OCCUPANCY 规则 + 定时任务 |
| **L4 全自动**  | PriceLabs / 途家 ML 模型  | 算法主导，人可覆盖 | ❌ 未实现           | 需求预测 + 竞品监控            |
| **L5 收益管理** | 酒店 RMS（置换成本+超售）       | 系统全局最优    | ❌ 未实现           | 长期目标                   |

## 七、可落地的演进路线

### 近期（1-2 周）：补齐 L2 建议型

1. 复用现有 `PriceAnalysisServiceImpl`
2. 新增 `GET /api/host/homestays/{id}/pricing-suggestion`
3. 前端房源管理页增加"价格建议"卡片，一键采纳写入 `pricing_rule`

### 中期（1 个月）：实现 L3 半自动

1. 新增 `OCCUPANCY` 规则类型
2. 每日凌晨定时任务：统计未来 N 天入住率 → 自动生成/更新 `DATE_RANGE` 规则
3. 自动规则标记 `autoGenerated = true`，房东可手动覆盖

### 远期（3-6 个月）：探索 L4 全自动

1. 竞品价格监控表 `competitor_price`
2. 需求预测模型（基于历史预订曲线）
3. 房东可设置"自动采纳建议价"或"仅提醒"

# 前端代码审查优化计划

> 项目: homestay3（民宿预订平台）
> 日期: 2026-05-15
> 涉及项目: homestay-front（用户端）+ homestay-admin（管理后台）

---

## 一、问题总览

| 优先级 | 问题 | 影响 | 涉及文件数 |
|--------|------|------|-----------|
| P0 | auth/user store 重复 | 状态不一致、维护困难 | 2+ stores, 多处引用 |
| P0 | 网络层分裂（两个 axios 实例） | API 行为不一致 | api/index.ts + utils/request.ts |
| P1 | 路由守卫直接读 localStorage | 绕过 Pinia、难测试 | router/index.ts |
| P1 | 大量 console.log 残留 | 生产环境噪音 | stores/*, router/* |
| P2 | 类型安全薄弱（any 泛滥） | 编译期无保护 | 多个 store/api 文件 |
| P2 | CSS 全局污染 + !important | 样式难以覆盖维护 | App.vue 等 |
| P3 | useSearchParams 竞态条件 | 搜索状态异常 | composables/useSearchParams.ts |
| P3 | v-permiss 指令无实际功能 | 权限形同虚设 | admin/main.ts |

## 二、分阶段执行计划

### Phase 1: 基础设施清理（低风险，快速见效）

**目标**: 消除噪音，统一基础层

- [x] **1.1 移除/条件化所有 console.log**
  - 范围: `homestay-front/src/stores/user.ts`, `router/index.ts`
  - 方案: 添加 `log()`/`warn()` 辅助函数，`import.meta.env.DEV` 条件输出
  - 实际耗时: 20min

- [x] **1.2 统一网络层**
  - 方案: `api/index.ts` 重新导出 `utils/request.ts` 实例，零引用变更
  - 涉及: `api/index.ts`
  - 实际耗时: 10min

- [x] **1.3 添加请求/响应日志级别控制**
  - front: 通过 `VITE_DEBUG_REQUESTS` 控制；admin: dev 默认 `debug`，prod 默认 `error`
  - 生产环境自动屏蔽 debug 日志
  - 实际耗时: 10min

### Phase 2: 状态管理重构（核心改动）

**目标**: 合并 auth/user store，消除重复

- [x] **2.1 设计统一 UserStore 接口**
  - 保留字段: token, userInfo, isAuthenticated, isLandlord, isAdmin
  - 保留方法: login, register, logout, fetchUserInfo, updateProfile, uploadAvatar, changePassword
  - 废弃: auth.ts 中重复的方法（迁移引用后删除）

- [x] **2.2 逐步迁移引用方**
  - 按优先级: router -> 组件 -> composables
  - 涉及 9 个文件，全部完成

- [x] **2.3 删除 stores/auth.ts**
  - 确认无引用后删除
  - 保留 stores/user.ts 作为唯一用户状态源

- [x] **2.4 迁移 localStorage 持久化到 Pinia 插件**
  - favorites.ts 已接入 `pinia-plugin-persistedstate`，移除手动 localStorage 管理
  - user.ts 保持手动持久化（与 request.ts interceptor 深度耦合，改动风险高）

### Phase 3: 类型安全增强

**目标**: 减少 any，定义统一 API 类型

- [x] **3.1 定义全局 API 响应类型**
  - 新建 `types/api.ts`

- [x] **3.2 为 store 错误处理定义类型**
  - 新建 `types/error.ts`

- [x] **3.3 逐步替换 store 中的 `error: any`**
  - user.ts / favorites.ts / search.ts 已全部替换为 typed error handling
  - 使用 `ApiRequestError` + `extractErrorMessage` 做类型收窄

### Phase 4: 路由与组件优化

- [x] **4.1 重构路由守卫**
  - 移除 localStorage 直接读取
  - 使用 `useUserStore()` 获取认证状态
  - 提取 `checkRoleMatch` 角色匹配函数

- [x] **4.2 修复 useSearchParams 竞态**
  - `isInternalUpdate` 改为 `ref`

- [x] **4.3 CSS 清理**
  - 移除 App.vue 全局 `!important`

- [x] **4.4 admin 端权限指令**
  - `v-permiss` 实现真实角色权限检查

### Phase 5: homestay-admin 对齐优化

- [x] **5.1 补充 build 类型检查**
  - `package.json` build 脚本添加 `vue-tsc --noEmit`

- [x] **5.2 统一错误处理风格**
  - 与 front 端保持一致的错误提示和日志级别

- [x] **5.3 移除路由 .catch() 异常处理**
  - 改用 `router.onError()` 全局处理

## 四、风险与回滚

| 风险 | 缓解措施 |
|------|----------|
| store 合并导致状态丢失 | 保持 localStorage key 不变，仅在 store 层面合并 |
| 网络层统一后行为变化 | 逐步替换，先统一 api 模块，再删除旧实例 |
| 路由守卫重构后权限失效 | 保留角色兼容逻辑（ROLE_HOST <-> ROLE_LANDLORD） |

# 前端性能优化-管理后台构建体积与交互

> [!summary] 一句话结论
> 消除 Element Plus 全量引入 + 手动分包后，管理后台主入口 chunk 从 **1,113.87 kB 降至 35.0 kB（-97%）**，gzip 358 → 14 kB；echarts/Element Plus/地区数据/vue 核心各自独立成 chunk，缓存友好、按路由按需加载。配套完成路由切换顶部进度条（零依赖）、分页逻辑 composable 抽取、统计导出双 bug 修复（假 xlsx + blob 不下载）。

## 一、优化前基线（2026-08-12 `npm run build`）

| chunk | 体积 | gzip |
|-------|------|------|
| index-DSlXz34i.js（主入口） | 1,113.87 kB | 357.84 kB |
| index-B_Vljoy8.js | 523.93 kB | 172.13 kB |
| installCanvasRenderer-Nw9gTn-V.js（echarts canvas） | 517.53 kB | 175.65 kB |
| element-china-area-data-DyMRb5Dq.js | 193.12 kB | 51.84 kB |

> 主 chunk 超 1MB 的根因：`main.ts` 中 `app.use(ElementPlus)` 全量注册组件 + 全量注册 300+ 图标，与已配置的 unplugin 按需解析冲突，整个库被打进主入口。

## 二、优化措施

| # | 措施 | 位置 |
|---|------|------|
| 1 | 移除 `app.use(ElementPlus)` 全量注册，组件改由 unplugin 按需导入（保留全局 `element-plus/dist/index.css` 与图标全量注册——侧边菜单依赖字符串图标） | `src/main.ts` |
| 2 | `ElementPlusResolver({ directives: true })` 按需注册 `v-loading` 等指令，避免移除全量注册后指令失效 | `vite.config.ts` |
| 3 | `manualChunks` 手动分包：element-plus / echarts+zrender / element-china-area-data / vue-core 独立 chunk，长缓存 + 按路由按需加载 | `vite.config.ts` |
| 4 | 路由切换顶部进度条（零依赖，reactive 状态 + CSS transition，beforeEach 开 / afterEach 收 / onError 兜底） | `src/router/index.ts`、`src/views/layout/index.vue` |
| 5 | 分页逻辑抽 `usePagination` composable（pageIndex/pageSize + buildParams 0-based 转换），LoginLog/OperationLog 两页复用 | `src/composables/usePagination.ts` |
| 6 | 统计导出双 bug 修复：后端假 `.xlsx`（内容实为 CSV）改 `.csv` + `text/csv`；前端 `statistics/index.vue` blob 拿到后不下载（只弹"导出成功"）补真实下载 | `AdminStatisticsController.java`、`src/views/statistics/index.vue` |

## 五、联动修复：路由快速切换白屏

> [!warning] 现象与根因
> 连续点击 5-6 个导航后页面变空白、后续点击无响应。根因：layout 的 `<transition mode="out-in">` 包裹**异步懒加载组件**，快速连续切换时 out-in 状态机与异步组件加载竞争，旧组件已退出、新组件不挂载，router-view 永久空白（Vue 已知坑）。

**修复**：移除 transition 包裹（切换反馈由顶部进度条承担），删除 fade 样式。commit `3cf40c5`。

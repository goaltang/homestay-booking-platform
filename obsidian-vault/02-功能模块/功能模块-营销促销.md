# 营销促销模块

> 营销促销模块提供平台优惠券的发放与核销、房东自主营销活动创建、平台级营销管理与 ROI 分析等功能，支撑平台的拉新、促活和增收策略。
> 路由：`/host/promotions`（房东端）、`/admin/marketing/*`（管理端） | 权限：`ROLE_USER`、`ROLE_HOST`、`ROLE_ADMIN`

## 一、功能清单

### 1.1 用户可见功能

| 功能 | 说明 |
|------|------|
| 可用优惠券列表 | C端用户可在“我的优惠券”中查看并管理可使用的优惠券 |
| 优惠券领取 | 允许用户在商品详情页或活动页手动领取处于激活状态的普通优惠券 |
| 下单优惠抵扣 | 用户下单确认页自动匹配并展示最优惠的券与活动，支持手动切换可用优惠券 |
| 房东活动管理 | 房东可在房东中心给自己名下的房源创建限时折扣（FLASH_SALE）与房源折扣（HOMESTAY_DISCOUNT）活动 |
| 房东营销统计 | 房东可查看自己创建活动带来的实收、总优惠额度以及单个活动的 ROI 分析图表 |

### 1.2 管理/系统功能

| 功能 | 说明 |
|------|------|
| 优惠券模板维护 | 管理员创建、激活、暂停、删除（仅限草稿状态）平台级或房东级优惠券模板 |
| 平台营销活动管理 | 管理员创建、审核并发布平台级营销活动（如全场满减、连住优惠等） |
| 优惠流水审计 | 全局优惠使用记录（`promotion_usage`）查询，便于财务稽核与对账 |
| 统一计价引擎 | `PricingService` 负责在报价与下单环节对房价进行一致性校验，防范篡改与价格溢出 |
| 营销数据总览 (ROI) | 提供平台级营销大盘数据，展示总活动数、GMV带动量、核销率及分摊比例 |

## 二、核心业务规则

### 2.1 状态定义

#### 营销活动生命周期状态 (PromotionCampaign Status)

| 状态 | 含义 | 触发条件 / 触发源 |
|------|------|-------------------|
| `DRAFT` | 草稿状态，不可被计价匹配，允许任意编辑与删除 | 创建活动时默认 |
| `ACTIVE` | 活动已激活并生效，可参与计价计算 | 管理员/房东点击发布（需满足开始与结束时间） |
| `PAUSED` | 活动暂停，计价时不匹配 | 管理员/房东手动点击暂停 |
| `ENDED` | 活动已结束，计价时不匹配，不能被重新启用 | 到达活动结束时间，或预算耗尽触发自动下架 |

#### 用户优惠券生命周期状态 (UserCoupon Status)

| 状态 | 含义 | 触发条件 / 触发源 |
|------|------|-------------------|
| `AVAILABLE` | 可用状态，可用于报价匹配与下单抵扣 | 用户领券成功，或订单取消/退款后释放回退 |
| `LOCKED` | 锁定状态，已被关联订单占用，无法被其他报价使用 | 用户提交下单，进入本地事务时锁定券 |
| `USED` | 已核销状态，表示优惠已实际享用 | 订单支付成功，由统一支付后置处理核销 |
| `EXPIRED` | 已过期失效，不再具备抵扣效力 | 超过有效截止时间，由定时任务 `CouponCleanupJob` 扫描变更 |

### 2.2 统一计价公式

系统采用固定计算链，顺序如下：
$$\text{每日基础房价} \rightarrow \text{周末/节假日加价} \rightarrow \text{早鸟/连住折扣} \rightarrow \text{限时促销/满减活动} \rightarrow \text{优惠券抵扣} \rightarrow \text{清洁费/服务费}$$

* **房东应收 (hostReceivableAmount)** = $\text{原始房费} - \text{房源折扣} - \text{活动房东承担} - \text{优惠券房东承担}$
* **平台补贴 (platformSubsidyAmount)** = $\text{活动平台承担} + \text{优惠券平台承担}$
* **实付金额 (payableAmount)** = $\text{优惠后房费} + \text{清洁费} + \text{服务费}$
* 价格下限保护：$\text{优惠后房费} = \max(\text{优惠前房费} - \text{活动优惠} - \text{优惠券优惠}, 0)$。如果总折扣超出最大折扣率限制（`coupon.max_discount.rate`），系统会对平台与房东的折后金额进行等比截断，防止产生负数账单。

### 3.3 状态管理

* 前端通过统一的 `useCrud` 状态模式封装活动与券模板的分页、搜索、删除等通用操作（详见：[[前端-useCrud-使用指南]]）。
* 交易环节使用后端生成的 `quoteToken` 进行防篡改校验。当用户在下单页面切换优惠券时，重新调用 `/api/pricing/quote` 获取最新的报价与令牌，保证前后端计价完全一致。

## 六、实时同步 / 特殊机制

1. **优惠券过期自动任务 (`CouponCleanupJob`)**
   * 系统每小时整点会通过定时任务扫描已过期的可用券（`expire_at < NOW` 且状态为 `AVAILABLE`），将其状态批量流转更新为 `EXPIRED`，实现闭环回收。
2. **防超用与安全并发控制**
   * **领券库存控制**：通过行锁 `templateRepository.findByIdForUpdate(templateId)` 对券库存进行锁定，以 `incrementIssuedCount` 对库存数量执行安全的原子更新，防范超发。
   * **下单预算扣除**：采用乐观锁对活动的已用预算进行并发更新，如果并发扣减导致活动预算不足，事务会即时回滚，订单取消创建。
3. **已发放激活模板的“白名单编辑”保护**
   * 状态已经变成 `ACTIVE`（已激活）的优惠券模板，出于安全和交易一致性考虑，仅允许修改 `name`、`validStartAt`、`validEndAt`、`status`、`totalStock` 和 `perUserLimit` 字段。所有涉及金额和优惠门槛的核心字段（如 `faceValue`、`discountRate` 等）一律处于只读保护状态。

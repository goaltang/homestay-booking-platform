# 定价引擎

> 提供房源动态报价计算及多维度价格策略管理。路由：`/api/pricing/*`, `/api/admin/pricing-rules/*`, `/api/host/pricing-rules/*` | 权限：`ADMIN`, `HOST`, `LANDLORD`, `USER`

## 一、功能清单

### 1.1 用户可见功能

| 功能 | 说明 |
|------|------|
| 查看实时计价明细 | C端用户在房源预订或确认订单时，可查看每日房费、周末溢价、节假日溢价、早鸟与连住优惠的具体扣减详情 |
| 管理个人定价规则 | 房东（HOST/LANDLORD）可查看、创建、修改及删除个人拥有的房源定价规则（仅限于 HOST、HOMESTAY 或 GROUP 作用域） |
| 管理全局定价规则 | 系统管理员（ADMIN）可查看、创建、修改及删除系统内所有规则，包括全局周末、节假日定价与早鸟、连住优惠等 |

### 1.2 管理/系统功能

| 功能 | 说明 |
|------|------|
| 定价动态计算引擎 | 在用户发起询价或下单时，实时拉取生效规则并以特定优先级级联计算出最终应付金额 |
| 节假日自动同步预置 | 系统内置 2026 年法定节假日及调休数据，替代传统的硬编码逻辑 |
| 节假日覆盖率定时监控 | 后台监控任务定期校验未来节假日数据完整性，预防因数据缺失造成的溢价计算失败 |

---

## 二、核心业务规则

### 2.1 规则优先级与叠加计算逻辑

1. **优先级顺序**（由低到高，`priority` 字段升序应用）：
   * `WEEKEND` (周末溢价)
   * `HOLIDAY` (节假日溢价)
   * `EARLY_BIRD` (早鸟折扣)
   * `LONG_STAY` (连住特惠)
2. **叠加与截断机制**：
   * 所有规则按照 `priority` 升序链式计算。
   * 若某条规则的 `stackable` (是否可叠加) 字段为 `false`，则在应用该规则后中断后续所有计价规则的计算。
3. **折扣换算说明**：
   * 采用 `DISCOUNT_RATE` 时，传入的值表示折扣比例（例如：`0.10` 代表扣减 10% 的金额，即打 9 折；`0.15` 代表扣减 15% 的金额，即打 85 折）。

### 2.2 角色权限与所有权规则

| 角色 | 权限范围 | 所有权限制 |
|------|----------|------------|
| **ADMIN** | 可操作所有作用域的规则（`GLOBAL`, `HOST`, `HOMESTAY`, `GROUP`） | **无限制**：由于无超级管理员之分，任意管理员可修改或删除包含系统预置、其他管理员创建的所有规则 |
| **HOST / LANDLORD** | 仅能创建或管理作用域为 `HOST`, `HOMESTAY`, `GROUP` 的规则 | **严格所有权**：仅能修改或删除其自身创建的规则，不能跨房东修改 |

## 三、页面与组件

### 3.1 路由

| 路径 | 组件 | 说明 |
|------|------|------|
| `/order/confirm` | `OrderConfirm.vue` | 订单确认页面（集成价格细分折叠面板） |
| 后台管理路径 | `PricingRuleManage.vue` | 定价规则管理列表与编辑表单 |

### 3.2 组件结构

```text
OrderConfirm.vue (订单确认主页)
└─ Price Breakdown Panel (价格折叠明细面板 - 新增)
   ├─ Daily Rate List (每日单价及溢价原因展示)
   └─ Discount Detail List (各项折扣金额及优惠说明展示)
```

### 3.3 状态管理

* 采用 **Caffeine** 本地高性能内存缓存维护计价规则状态（缓存区名称 `pricingRules`）。
* 在执行规则的更新、修改、删除和状态切换操作时，自动触发 Spring 缓存驱逐（`@CacheEvict(allEntries = true)`），保持强一致性。

## 五、数据模型

### 5.1 数据库表

#### 1. 价格规则表 (`pricing_rule`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | bigint (PK) | 规则自增唯一标识 |
| `name` | varchar(100) | 规则名称 |
| `scope_type` | varchar(20) | 作用域：`GLOBAL`, `HOST`, `HOMESTAY`, `GROUP` |
| `scope_value_json` | text | 作用域值，例如 `{ "homestayId": 1 }` 或 `{ "hostId": 2 }` |
| `rule_type` | varchar(20) | 规则类型：`WEEKEND`, `HOLIDAY`, `EARLY_BIRD`, `LONG_STAY` |
| `adjustment_type` | varchar(20) | 调整类型：`MULTIPLY`, `DISCOUNT_RATE` 等 |
| `adjustment_value` | decimal(10,2) | 调整系数值 |
| `priority` | int | 计算优先级（数值越小优先级越低，越先计算） |
| `stackable` | boolean | 是否允许与其它规则叠加 |
| `start_date` | date | 规则生效开始日期 |
| `end_date` | date | 规则生效结束日期 |
| `min_nights` | int | 连住天数阈值 |
| `min_advance_days` | int | 早鸟提前天数阈值 |
| `enabled` | boolean | 是否启用 |
| `created_by` | bigint | 创建人用户 ID |

#### 2. 节假日日历表 (`holiday_calendar`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | bigint (PK) | 主键 |
| `date` | date | 具体日期 |
| `name` | varchar(50) | 节日/调休名称 |
| `type` | varchar(30) | 类型：`PUBLIC_HOLIDAY`, `MAKEUP_WORKDAY` |
| `region_code` | varchar(10) | 地区代码（默认 CN） |
| `is_holiday` | boolean | 是否放假 |
| `is_makeup_workday` | boolean | 是否补班调休 |

## 六、实时同步 / 特殊机制

1. **本地多级缓存退避**：
   * 鉴于原有分布式 Redis 缓存连接不稳定带来的响应延迟，定价规则缓存使用 **Caffeine 本地缓存**，报价令牌仍使用 Redis。
   * 配置缓存区 `pricingRules`，设置 TTL 限制为 5 分钟，最大内存承载容量为 10 条。
2. **节假日监控定时任务**：
   * 采用后台定时线程，每日自动扫描节假日数据。
   * 当未来 30 天内包含公共法定节假日但日历表中无配置记录时，触发预警，避免计算周末及特殊价格异常。

# 订单管理模块

> 订单管理模块负责处理用户的预订订单，包括订单查看、状态更新、退款处理等功能。路由：`/orders` | 权限：`ADMIN`

## 一、功能清单

### 1.1 用户可见功能（按用户操作视角分类）

| 功能 | 说明 |
|------|------|
| 查看订单列表 | 查看所有预订订单，支持分页 |
| 按状态筛选 | 待支付、已支付、已入住、已完成、已取消、退款中 |
| 按时间范围筛选 | 入住日期范围、创建日期范围 |
| 订单搜索 | 订单号、住客名称、房源标题、房东名称 |
| 查看订单详情 | 订单基本信息、入住人信息、房源信息、支付明细 |
| 异常订单统计 | 仪表盘展示待处理超时、支付失败、退款失败等异常订单数 |

### 1.2 管理/系统功能

| 功能 | 说明 |
|------|------|
| 确认订单 | 管理员手动确认订单支付 |
| 取消订单 | 管理员强制取消订单 |
| 退款处理 | 直接执行退款、审批退款申请、拒绝退款 |
| 争议仲裁 | 发起争议、解决争议（APPROVED/REJECTED） |
| 导出订单 | 导出 Excel 格式的订单数据 |
| 批量操作 | 批量发起退款、批量强制取消、批量导出 |

## 二、核心业务规则

### 2.1 订单状态机

```
待支付 → 已支付 → 已入住 → 已完成
   ↓        ↓
已取消   退款中 → 已退款
```

| 状态 | 说明 |
|------|------|
| PENDING | 待支付 |
| PAID | 已支付 |
| CHECKED_IN | 已入住 |
| COMPLETED | 已完成 |
| CANCELLED | 已取消 |
| REFUNDING | 退款中 |
| REFUNDED | 已退款 |

### 2.2 退款规则

- 管理员直接退款：类型为 `ADMIN_INITIATED`，无需审批
- 管理员审批退款：仅限 `HOST_CANCELLED` 类型的退款申请
- 拒绝退款需填写拒绝原因

## 三、页面与组件

### 3.1 路由

| 路径 | 组件 | 说明 |
|------|------|------|
| `/orders` | `order/list.vue` | 订单列表页 |

### 3.2 组件结构

```
order/list.vue
├── 异常订单统计卡片（stats-grid）
├── 当前筛选提示（el-alert）
├── 搜索区域（search-box）
│   ├── 基础搜索（订单号、住客名称、订单状态）
│   └── 高级搜索（房源标题、房东名称、支付状态、支付方式、入住日期范围、创建日期范围）
├── 批量操作悬浮条（batch-operation-bar）
└── 订单表格（el-table）
    ├── 多选列
    ├── 订单号（可排序）
    ├── 房源信息
    ├── 客人信息
    ├── 入住信息（可排序）
    └── ...操作列
```

### 3.3 状态管理

- 页面级状态：`searchForm`、`loading`、`tableData`、`selectedRows`
- 排序状态：`sort` 参数通过 `handleSortChange` 更新，支持多字段排序

## 四、后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/orders` | 获取订单列表（分页+筛选+排序） |
| GET | `/api/admin/orders/exception-stats` | 获取异常订单统计 |
| GET | `/api/admin/orders/{id}` | 获取订单详情 |
| PUT | `/api/admin/orders/{id}/status` | 更新订单状态 |
| PUT | `/api/admin/orders/{id}/confirm-payment` | 手动确认支付 |
| POST | `/api/admin/orders/{id}/refund` | 直接执行退款 |
| POST | `/api/admin/orders/{id}/refund/approve` | 审批退款申请 |
| POST | `/api/admin/orders/{id}/refund/reject` | 拒绝退款申请 |
| POST | `/api/admin/orders/{id}/dispute` | 发起争议 |
| POST | `/api/admin/orders/{id}/dispute/resolve` | 解决争议 |
| DELETE | `/api/admin/orders/{id}` | 删除订单 |
| GET | `/api/admin/orders/export` | 导出订单 |

### 4.1 核心 Service

- `OrderService.getAdminOrders(Pageable, ...)` — 管理员订单查询
- `PaymentProcessingService.executeRefund(...)` — 退款执行
- `DisputeService.raiseDispute(...)` / `resolveDispute(...)` — 争议处理

## 五、数据模型

### 5.1 数据库表（核心字段）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| order_number | VARCHAR | 订单号 |
| homestay_id | BIGINT | 房源ID |
| user_id | BIGINT | 用户ID |
| check_in_date | DATE | 入住日期 |
| check_out_date | DATE | 退房日期 |
| total_amount | DECIMAL | 订单总金额 |
| status | VARCHAR | 订单状态 |
| payment_status | VARCHAR | 支付状态 |
| payment_method | VARCHAR | 支付方式 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

## 六、实时同步 / 特殊机制

- **多字段排序**：后端通过 `SortUtils.parseSort()` 支持 `sort=createdAt,desc;id,asc` 格式，字段映射+白名单校验
- **批量操作**：前端选择多行后显示批量操作悬浮条

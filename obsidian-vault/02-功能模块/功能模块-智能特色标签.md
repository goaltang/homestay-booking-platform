# 智能特色标签

> 从 8 个维度自动生成房源特色标签并在房源详情页展示，同时根据用户搜索条件动态提升匹配标签优先级。路由：`/homestays/:id` | 权限：公开浏览

## 一、功能清单

### 1.1 用户可见功能（按用户操作视角分类）

| 分类 | 功能 | 说明 |
|------|------|------|
| 查看 | 查看房源特色标签 | 在房源详情页看到系统生成的特色卡片（标题、描述、图标） |
| 查看 | 查看搜索条件匹配标签 | 当搜索结果命中特定特色时，对应标签会优先展示在前列 |
| 查看 | 查看房东特色徽章 | 在房东信息区展示由特色标签衍生的房东成就徽章 |

### 1.2 管理/系统功能

| 功能 | 说明 |
|------|------|
| 多维度特色分析 | 系统从房源类型、价格竞争力、设施组合、位置优势、预订活跃度、周末流行度、用户评价、入住便利性 8 个维度计算特色 |
| 搜索条件提权 | 根据传入的搜索条件（`referringSearchCriteria`）对匹配的特色标签优先级 +50 |
| 权重系统 | 根据房源类型、价格段、城市区域、季节等因素动态调整各维度优先级 |
| 多维度平衡 | 每个维度最多只产出 1 个特色，避免单一维度堆砌 |

## 二、核心业务规则

### 2.1 分析维度与输出规则

| 维度 | 触发条件 | 输出特色示例 | 基础优先级 |
|------|----------|--------------|------------|
| 房源类型 | 根据 `type` + `maxGuests` | 传统民居 / 家庭式公寓 / 豪华别墅 / 特色住宿 | 11 |
| 价格竞争力 | 价格分析服务返回竞争力等级 | 超值选择 / 高性价比 / 价格优势 / 市场价格 | 6~12 |
| 设施组合 | 同时命中组合规则中的多个设施 | 商务办公 / 亲子友好 / 娱乐设施 / 厨房设施 / 四季舒适 | 6~10 |
| 单一设施 | 无组合命中时取优先级最高的单一设施 | 高速 WiFi / 停车位 / 空调 / 洗衣机等 | 5 |
| 位置优势 | 根据 `cityCode` 匹配城市描述 | 一线城市核心区域 / 旅游城市描述 / 通用位置文案 | 6 |
| 预订活跃度 | 最近 120 天有效订单数 ≥ 1 | 近期热门 | 10 |
| 周末流行度 | 最近 12 个月订单中周五/周六入住比例 ≥ 30% | 周末优选 | 7 |
| 用户评价 | 公开评价 ≥ 3 条，按平均评分 / 关键词统计 | 好评如潮 / 评价良好 / 住客称赞「干净」等 | 6~8 |
| 入住便利性 | 设施中包含「自助入住」「密码锁」或「24 小时入住」 | 便捷入住 | 5 |

### 2.2 价格竞争力等级

价格竞争力由 `PriceAnalysisService.analyzePriceCompetitiveness()` 输出，等级定义如下：

| 等级 | 触发条件 | 生成的特色 | 优先级 |
|------|----------|------------|--------|
| EXTREMELY_COMPETITIVE | 低于市场均价 30% 以上 | 超值选择 | 12 |
| HIGHLY_COMPETITIVE | 低于市场均价 15%~30% | 高性价比 | 10 |
| COMPETITIVE | 低于市场均价 5%~15% | 价格优势 | 9 |
| MARKET_RATE | 与市场均价差距在 ±5% | 市场价格 | 6 |
| PREMIUM | 高于市场均价 20% 以上 | 旺季精选（仅旺季） | 6 |
| ABOVE_MARKET | 高于市场均价 5%~20% | 不生成特色 | - |

### 2.3 搜索条件提权规则

| 字段 | 规则 |
|------|------|
| 触发条件 | `referringSearchCriteria` 不为空且包含与 `featureId` 完全匹配的字符串（忽略大小写） |
| 提权数值 | 命中的特色 `priority += 50` |
| 可叠加 | 多个条件命中同一 featureId 时重复累加 |

### 2.4 权重系统加成项

| 加成类型 | 适用特色 | 加成条件 | 加成值 |
|----------|----------|----------|--------|
| 低价房源价格加成 | `PRICE_*` | `price ≤ 200` | +0.3 |
| 高端房源组合加成 | `FAMILY_FRIENDLY_*` / `REMOTE_WORK_*` | `price > 300` | +0.2 |
| 市中心位置加成 | `LOCATION_*` | `districtText` 包含市中心/中心区/市区 | +0.3 |
| 郊区停车/交通加成 | 含 `PARKING` / `TRANSPORT` | `districtText` 包含郊区/新区 | +0.2 |
| 别墅类型加成 | `PROPERTY_TYPE_*` / 家庭宠物相关 | `type == VILLA` | +0.4 / +0.3 |
| 公寓类型加成 | `LOCATION_*` / `CONVENIENT_*` / `REMOTE_WORK_*` | `type == APARTMENT` | +0.3 / +0.2 |
| 传统民居加成 | `PROPERTY_TYPE_*` / 含「传统」的评价 | `type == TRADITIONAL` | +0.3 / +0.4 |
| 特色住宿加成 | `PROPERTY_TYPE_*` / `REVIEW_*` | `type == UNIQUE_STAY` | +0.5 / +0.2 |
| 夏季户外加成 | 含 `POOL` / `GARDEN` / `BALCONY` / `WEEKEND_*` | 6~8 月 | +0.1~0.2 |
| 冬季取暖加成 | 含 `HEATING` / `WARM` / `FAMILY_FRIENDLY_*` | 12~2 月 | +0.1~0.3 |
| 假期活跃度加成 | `POPULAR_*` / `WEEKEND_*` / `PRICE_*` | 1~2 月、7~8 月、10 月 | +0.1~0.2 |

### 2.5 状态字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `featureId` | String | 特色唯一标识，如 `PROPERTY_TYPE_VILLA`、`PRICE_HIGHLY_COMPETITIVE`、`AMENITY_WIFI` |
| `iconName` | String | Element Plus 图标名称，前端动态映射为组件 |
| `title` | String | 特色标题，展示在卡片主文案 |
| `description` | String | 特色详细说明 |
| `priority` | Integer | 排序优先级，数值越大越靠前；最终值 = 基础值 × 权重 + 搜索提权 |

## 三、页面与组件

### 3.1 路由

| 路径 | 组件 | 说明 |
|------|------|------|
| `/homestays/:id` | `HomestayDetail.vue` | 房源详情页，展示特色标签列表 |

### 3.2 组件结构

```
HomestayDetail.vue
└── FeaturesList.vue
    ├── feature-item-re（特色卡片，循环渲染）
    │   ├── feature-icon-wrapper（图标）
    │   └── feature-text（标题 + 描述）
    └── 空状态 fallback（无特色时展示默认文案）
HostInfo.vue
└── host-highlights（房东成就徽章区）
```

### 3.3 状态管理

特色标签由后端 `HomestayDtoAssembler` 在组装 `HomestayDTO` 时调用分析服务生成，通过接口一次性返回给前端；前端仅做展示和图标映射，不做额外状态管理。

## 四、后端接口

### 4.1 对外接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/homestays/{id}` | 房源详情接口，返回的 `HomestayDTO.suggestedFeatures` 包含智能特色标签 |

### 4.2 核心 Service

| 类/接口 | 说明 |
|------|------|
| `HomestayFeatureAnalysisService` | 分析服务接口 |
| `HomestayFeatureAnalysisServiceImpl` | 分析服务实现，包含 8 个维度分析、搜索提权、权重系统 |
| `HomestayDtoAssembler.enrichSuggestedFeatures` | 组装 DTO 时调用分析服务 |
| `PriceAnalysisService` | 价格竞争力分析依赖服务 |

## 五、数据模型

### 5.1 数据库表

特色标签为运行时计算产物，不单独持久化；依赖以下表：

| 表名 | 主要字段 | 用途 |
|------|----------|------|
| `homestays` | `id`, `type`, `price`, `max_guests`, `city_code`, `district_code`, `district_text` | 房源类型、价格、位置分析 |
| `amenities` | `value`, `label`, `description`, `icon`, `category_code` | 设施组合与单一设施分析 |
| `homestay_amenity` | `homestay_id`, `amenity_id` | 房源与设施关联 |
| `orders` | `id`, `homestay_id`, `status`, `check_in_date`, `created_at` | 预订活跃度、周末流行度分析 |
| `reviews` | `id`, `homestay_id`, `rating`, `content`, `is_public`, `deleted` | 用户评价分析 |

### 5.2 DTO / 类型定义

| DTO | 字段 | 说明 |
|------|------|------|
| `SuggestedFeatureDTO` | `featureId`, `iconName`, `title`, `description`, `priority` | 单个特色标签 |
| `PriceCompetitivenessDTO` | `competitivenessLevel`, `priceDifferenceFromAverage`, `comparisonScope`, `seasonalPeak` 等 | 价格竞争力结果 |
| `HomestayDTO` | `suggestedFeatures: List<SuggestedFeatureDTO>` | 房源详情返回体 |

## 六、实时同步 / 特殊机制

特色标签在每次请求房源详情时实时计算，不依赖缓存或定时任务，确保能反映最新订单和评价状态。

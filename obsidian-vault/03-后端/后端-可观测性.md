# 后端可观测性（Actuator + Micrometer + Prometheus + Grafana）

> [!info] 概述
> 2026-08-12 落地。健康检查、指标端点、业务埋点、抓取与可视化四层齐备，让限流/重试/降级/并行化等既有能力"看得见、可验证"。

## 架构链路

```text
后端（8081）
  └─ /actuator/prometheus（Micrometer 暴露 Prometheus 格式指标）
       └─ Prometheus 容器（15s 抓取，host.docker.internal:8081）
            └─ Grafana 容器（数据源自动注册 + dashboard 自动加载）
```

## 端点与配置

| 端点 | 说明 |
|---|---|
| `/actuator/health` | 健康检查（show-details=always，含 Redis/DB/ES 组件状态） |
| `/actuator/prometheus` | Prometheus 格式指标（Security 已放行） |
| `/actuator/metrics` | Micrometer 指标查询 |

配置键（application.properties）：

```properties
management.endpoints.web.exposure.include=health,info,prometheus,metrics
management.endpoint.health.show-details=always
management.metrics.tags.application=homestay
```

## 业务埋点（6 类，homestay.* 前缀）

| 指标 | 位置 | 说明 |
|---|---|---|
| `homestay.ratelimit.blocked{method}` | RateLimitAspect | 限流触发次数（429 计数），method=类名.方法名 |
| `homestay.mq.consumed{scenario}` | 三个 MQ Consumer | 成功消费数，scenario=order.timeout/coupon.batch/notification.push |
| `homestay.mq.retried{scenario}` | 三个 MQ Consumer | 消费失败进重试队列次数 |
| `homestay.order.timeout.cancelled` | OrderTimeoutService | 超时取消订单数（三处取消路径） |
| `homestay.llm.requests{result}` | LlmClient | LLM 调用成功/失败计数（result=success/failure） |
| `homestay.home.stats.duration` | HomeService | 首页统计接口耗时 Timer（五路并行化的量化验证） |

埋点实现：`config/MetricsConfig.java` 纯静态工具类（`increment(registry, name, tags...)`），registry 为 null 静默跳过——纯 Mockito 单测不受影响；各埋点处注入 `MeterRegistry` 直接调用。**埋点只加不改，不改变业务逻辑与异常路径**（限流计数在 try 外计算 method 标签，不向降级 catch 引入新异常）。

## 监控基建（docker-compose）

| 服务 | 端口 | 账号 | 说明 |
|---|---|---|---|
| prometheus | 9090 | — | 抓取 `host.docker.internal:8081/actuator/prometheus`，15s 间隔（tools/monitoring/prometheus.yml） |
| grafana | 3000 | admin/admin123 | 数据源自动注册（provisioning）+ dashboard 自动加载（tools/monitoring/grafana-dashboard.json） |

Grafana Dashboard 4 面板：
1. JVM 堆内存（jvm_memory_used_bytes, area=heap）
2. HTTP 请求量 QPS（rate(http_server_requests_seconds_count[5m])）
3. 限流触发次数（increase(homestay_ratelimit_blocked_total[5m])）
4. 首页统计耗时 p95（histogram_quantile）

> WSL/Docker Desktop 场景：容器通过 `host.docker.internal` 访问宿主机后端，后端需在宿主机以 `mvn spring-boot:run` 启动。

## 测试

- `src/test/java/.../observability/ObservabilityMetricsTest.java`：3 用例——prometheus 端点 200 且含 jvm_memory；限流 counter 打点后出现在导出；MQ/LLM/Timer 业务埋点全部导出。注意 `@AutoConfigureObservability`（@SpringBootTest 默认关闭指标导出，不加会 404）

## 排障记录（实现期 4 个真实 bug）

1. MetricsConfig 初版 `@Configuration` + private 构造器 → CGLIB 启动报错；改纯静态工具类
2. 限流埋点 method 标签在 try 内计算 → mock 下 NPE 被降级 catch 吞掉、超限静默放行；移到 try 外
3. @SpringBootTest 默认经 DisableObservabilityContextCustomizer 关指标导出 → /actuator/prometheus 404；测试加 @AutoConfigureObservability
4. ApplicationIntegrationTest health 断言漏了 503（ES 未起时合法健康状态）

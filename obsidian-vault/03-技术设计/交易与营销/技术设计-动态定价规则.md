# 技术设计-动态定价规则

本页说明现有规则机制，管理功能见 [[功能模块-定价引擎]]；早期设计见 [[方案-定价引擎]]。

## 两个阶段

| 阶段 | PricingEngineServiceImpl 入口 | 内容 |
|---|---|---|
| 日期级 | calculateDailyPrices | 每个住宿日匹配范围、日期、周末或节假日规则 |
| 入住级 | calculateStayDiscounts | 按入住日期、晚数、提前天数匹配折扣 |

统一计价先汇总日期级价格，再计算入住折扣，后续进入活动与券优惠。

## 匹配与调整

| 项目 | 当前行为 |
|---|---|
| 范围 | matchesScope 匹配规则范围与房源 |
| 条件 | matchesRule 检查日期、晚数、提前天数等 |
| 调整 | applyAdjustment 按类型改变价格或乘数 |
| DISCOUNT_RATE | 扣减比例，使用 1 - value；0.1 表示扣减 10% |
| 规则缓存 | CacheConfig 的 pricingRules：Caffeine，TTL 5 分钟、最大 10 条配置 |
| 报价缓存 | 统一计价服务使用 Redis，与规则缓存不同 |

## 数据与代码

| 入口 | 作用 |
|---|---|
| PricingRule / PricingRuleRepository | 规则模型和读取 |
| AdminPricingRuleService / HostPricingRuleService | 规则管理 |
| holiday_calendar / pricing_rule | 节假日与规则持久化 |
| PricingEngineServiceImpl | 计算 |
| CacheConfig | 本地缓存 |

核对了规则计算与缓存分工，没有测试所有规则组合或重新测量性能。完整关系见 [[技术设计-统一计价与优惠券]]。

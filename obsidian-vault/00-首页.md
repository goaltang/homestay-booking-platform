## 文档分类

| 目录 | 放什么 | 怎么读 |
|---|---|---|
| `01-项目说明/` | 项目定位、技术栈、三端职责、启动入口 | 了解项目的起点 |
| `02-功能模块/` | 按业务域归类的功能、规则和页面 | 查用户能做什么、业务如何流转 |
| `03-技术设计/` | 前后端机制、AI 权限、共享设计 | 查实现原因与代码入口 |
| `04-验证与复盘/` | 有日期的测试、压测、审查、故障记录 | 查看当时的条件和结论 |
| `05-方案与规划/` | 待评审方向、待实施内容、历史方案 | 不能据此认定当前功能已经实现 |
| `90-学习笔记/` | Git 手册与行业参考 | 学习资料，不作为项目实现依据 |
| `98-文档规范/` | 分类、模板和维护约定 | 写文档前查规则 |
| `99-求职准备/` | 简历、面试话术、个人素材 | 本地保留，Git 忽略；克隆仓库不会包含它 |

业务模块分为房源与搜索、预订与履约、房东与营销、用户与互动、平台运营。共享内容通过链接引用，避免重复抄写。

## 如何判断一篇文档能否当作当前事实

看笔记属性中的 `status`：

| 状态 | 含义 |
|---|---|
| 已核对 | 指定范围已对照当前代码或配置静态核对，不表示重新跑过测试 |
| 待核对 | 旧说明已归位，完整业务描述还需要核对 |
| 历史记录 | 保留原时间点的结果与设计，不自动代表今天的实现 |
| 待评审 / 部分落地 | 仍有设计选择或未完成事项，需要逐项确认 |
| 参考资料 | 通用知识或行业观察，不代表本项目采用 |
| 维护中 | 导航、目录或文档规则 |

`date` 保留原记录日期，`updated` 是整理日期，`reviewed` 才是代码核对日期。测试是否通过，以报告实际运行日期、条件和结果为准。

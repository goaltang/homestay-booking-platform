## 五、可能被问的问题与回答要点

> [!tip] 面试前自检
> 每条要能用 1-2 分钟讲清楚，重点是"为什么这么做"而不是"做了什么"。

### Q1：定价引擎怎么设计的？

**要点**：
- 多策略叠加：基础价 → 节假日溢价 → 连住折扣 → 早鸟优惠
- 优先级 + 作用域（全局/城市/房东/房源组/单房源）
- 订单生成时**快照锁定价格**，避免规则变更影响历史订单
- 节假日识别：内置中国节假日数据 + 调休补班识别

### Q2：分布式锁怎么保证不误删？

**要点**：
- 基于 Redis `SET key value NX PX` 加锁
- 锁 value 写入唯一 token（UUID）
- 释放锁时用 **Lua 脚本**：`if redis.call("get",KEYS[1]) == ARGV[1] then return redis.call("del",KEYS[1])`
- Redis 不可用时**降级为无锁**（依赖数据库唯一索引兜底）
- `ConcurrentBookingTest` 集成测试用 H2 模拟并发

### Q3：推荐系统的三级降级是什么？

**要点**：
- L1：个性化推荐（ES + 用户画像 + 行为权重）
- L2：协同过滤/相似房源
- L3：热门房源（Redis 缓存 + 全局排序）
- 任一级失败自动降级，保证接口可用性

### Q4：为什么用 ES 不用 MySQL？

**要点**：
- 房源搜索需要**全文检索 + 多字段筛选 + Geo 查询**
- MySQL `LIKE '%keyword%'` 无法走索引，大数据量全表扫
- ES IK 分词器支持中文，性能提升 10-100 倍
- 提供 JPA 降级方案：ES 故障时 MySQL Specification 兜底

### Q5：RabbitMQ 怎么保证消息不丢？（新增重点）

**要点**：
- 三场景共用统一模式：**主队列 + 重试/延迟队列（TTL 死信回主）、消费者手动 ack + 幂等校验、mq-enabled 开关降级、定时任务兜底对账**
- 订单超时：下单发 TTL 2h 延迟队列 → DLX 死信转入消费队列 → 幂等校验后系统取消；定时任务扫三级超时场景（待确认/待支付/支付中）兜底
- 批量发券：消费者逐条入账，失败进重试队列，60s 后死信回流自动重试 ≤3 次
- 通知推送：**事务提交后**才发送，WebSocket 实时推送，进程崩溃消息不丢、重启后自动补推
- 追问准备：为什么用 DLX 延迟队列不用延迟插件？（rabbitmq_delayed_message_exchange 插件需额外安装且性能差，DLX+TTL 是原生方案；缺点是队列内 TTL 只对队首生效——本项目每种超时时长独立队列规避）

### Q6：AI 客服的写操作权限怎么设计的？（新增重点）

**要点**：
- **三层权限矩阵**：L1 FAQ 只读工具（7 个）；L2 申请型写工具（退款/取消/争议 3 个）——**只起草不执行**，返回 `pendingAction`；L3 争议辅助 `DisputeAdvisor` 只生成裁决建议草稿，**绝不自动仲裁**
- 写操作两段式：LLM 编排产出 pendingAction → 前端确认卡片展示摘要 → 用户批准走 `POST /api/support/agent/confirm` 才调用真正的 Service
- **10 工具白名单硬编码**在 `AgentToolRegistry`；禁区工具（approveRefund / executeRefund / deleteOrder 等）根本不在注册表里
- `OrderAccessGuard.requireGuestOrder` 强校验订单客人身份，越权抛 AccessDeniedException
- 测试保障：48 个后端用例断言起草模式（verify 未调用 service 写方法）、越权拒绝、禁区隔离；5 个前端组件用例覆盖确认卡片交互
- 一句话总结：**LLM 只有建议权，执行权永远在用户和后端校验手里**

### Q7：可观测性做了什么？性能数字怎么来的？（新增）

**要点**：
- Actuator + Micrometer + Prometheus + Grafana，6 类业务埋点（限流触发/MQ 重试积压/订单超时/LLM 调用/首页统计）
- 性能数字全部来自 vault 压测报告，可复现：首页统计并行化 P95 105→50ms（-52%）；下单 p95 128→85ms、p99 1.38s→110ms
- 压测方法论：独立 MySQL 3307 + Redis 6380 与开发库隔离；容量基线结论"瓶颈是开发机内存，不是应用层"

### Q8：AI 工具用得多吗？你负责什么？

**要点**：
- 工具链：Cursor Pro → Claude Code CLI → Kimi Code CLI
- AI 负责：编码提效、样板代码、补全测试
- **我负责**：架构设计、需求决策、代码审查、关键模块攻关（分布式锁、定价引擎、MQ 可靠投递、Agent 权限矩阵这些关键决策都是人工设计）
- 反将一军：我不仅用 AI 写代码，还设计了 LLM 安全接入业务系统的权限方案（Q6）

### Q9：三端怎么协同？代码怎么复用？

**要点**：
- 三端是**独立前端项目**（front / admin），后端共用一套 API
- 同一套 DTO + 统一响应 `ApiResponse<T>`
- 后端按 `ROLE_USER` / `ROLE_HOST` / `ROLE_ADMIN` 区分权限
- 前端公共逻辑沉淀为组合式函数（如 useCrud）与统一 HTTP 层
